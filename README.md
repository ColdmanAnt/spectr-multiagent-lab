# СПЕКТР — последняя смена

Многоагентная система управления вымышленной исследовательской лабораторией для курса «Теория многоагентных систем».

**Выполнил:** Холодков Антон Евгеньевич, НИЯУ МИФИ, Б24-517.

**Преподаватель:** Евгений Николаевич Лагунцев.

Три научные группы конкурируют за три измерительные установки и двух транспортных роботов. Система реализует диспетчеризацию, контрактную сеть, переговоры об очереди и защиту от нарушений. Все правила заданы в исходном коде. Ресурсы и длительности условны; реальные ядерные процессы не моделируются.

## Запуск

Требуется **Node.js 20 или новее**. Сторонних пакетов нет; `npm install` не требуется.

```sh
git clone https://github.com/ColdmanAnt/spectr-multiagent-lab.git
cd spectr-multiagent-lab
node server.mjs
```

При скачивании через **Code → Download ZIP** распакуйте архив и выполните `node server.mjs` из папки с `package.json`.

Откройте **http://127.0.0.1:4173**. Другой порт: `node server.mjs --port 8080`.

Приложение работает без учётных записей, ключей и внешних сервисов. Сервер выдаёт статические файлы; симуляция выполняется в браузере. `index.html` нужно открывать через HTTP, а не двойным щелчком.

## Развёртывание на своём сервере

Папка **`dist/`** содержит готовый сайт. Скопируйте её содержимое в корневую папку любого статического HTTP-сервера, например nginx или Apache. Установка пакетов и сборка не нужны. Для `.js` должен выдаваться корректный JavaScript MIME-тип.

Встроенный `server.mjs` предназначен для локального запуска и слушает `127.0.0.1`. При использовании его на сервере можно настроить обратный прокси. Файлы отчётов и экспериментов для работы веб-интерфейса не требуются.

## Демонстрация

1. Выберите готовый режим или настройте координацию, сценарий, переговоры и защиту вручную. Изменение настроек начинает новую смену.
2. Запустите смену либо используйте «Один такт» и «+10 тактов». Темп меняет только скорость просмотра.
3. На вкладке «Агенты» изучите цели и локальные действия участников. В журнале доступны назначения, предложения, встречные предложения, согласия и отказы.
4. В «Аналитике смены» просмотрите программы групп, очереди и сроки. Нажатие на исследование открывает паспорт с фактической историей образца и ставит смену на паузу.
5. Для сравнения сохраните контрольный снимок, повторите тот же seed с другой настройкой и перейдите к тому же такту. Сравнение требует одинаковых исходных задач и горизонта; ручные сбои следует повторять на тех же тактах. Контроль хранится в памяти страницы до её перезагрузки.
6. Выгрузите полную трассу JSON из журнала, краткую сводку из аналитики или CSV серии на вкладке «Эксперименты».

Оценки аналитики относятся к текущей очереди и известному остатку доставки. Новые назначения, переговоры, сбои и повторные измерения могут изменить сроки. Если доставка неизвестна, оценка отсутствует. После завершения смены будущие сроки не прогнозируются.

## Проверка и повторение исследований

Запуск всех 28 тестов:

```sh
node --test tests/engine.test.mjs tests/analytics.test.mjs
```

Повторение полной серии и сохранение трасс:

```sh
node experiments.mjs --seeds 20 --scenario all --horizon 180 --compare-protection --out results/reliability
node tools/capture_evidence.mjs
node tools/measure_completion.mjs
```

Полная серия содержит **800 смен**: 20 seed × 5 сценариев × 2 механизма распределения × 2 режима переговоров × 2 режима защиты. Для сравнения используются одинаковые начальные задачи. `capture_evidence.mjs` сверяет сохранённую серию с движком и записывает 12 трасс, контрольные суммы и результат 18 тестов движка. Дополнительные 10 тестов проверяют аналитику интерфейса.

`measure_completion.mjs` повторяет 40 штатных смен для ЛР2: по 20 seed для двух механизмов, переговоры выключены, защита включена. Время до результата усредняется по достоверно завершённым задачам каждой смены, затем по 20 прогонам. Незавершённые задачи подсчитаны отдельно; разные механизмы могут завершать разные подмножества задач.

`runs.csv` хранит отдельные прогоны, `summary.csv` — средние и выборочные стандартные отклонения, `experiment.json` — настройки и полные данные. `coordination-times.json` содержит прямую временную метрику. Команды заменяют соответствующие результаты; временные отметки выгрузки могут измениться. Справка по параметрам: `node experiments.mjs --help`.

## Отчёты

В `reports/` находятся четыре отдельных отчёта в **DOCX и PDF**:

| Работа | Содержание |
| --- | --- |
| ЛР1 | Спецификация, роли, состояния, полномочия, диаграммы и архитектура |
| ЛР2 | Сравнение диспетчеризации и контрактной сети, время, сообщения и стоимость координации |
| ЛР3 | Переговоры при конкуренции за ресурсы, эффективность, справедливость и ограничения |
| ЛР4 | Неблагоприятные сценарии, трассы, защитные механизмы и оценка надёжности |

Исходники и полные экспериментальные данные предоставлены отдельно от отчётов.
