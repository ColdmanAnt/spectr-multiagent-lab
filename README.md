# СПЕКТР — последняя смена

Интерактивная многоагентная модель вымышленной ядерной исследовательской лаборатории. Научные группы конкурируют за измерительные установки, роботы перевозят контейнеры, агенты договариваются об очередности работ. Сбои проверяют устойчивость системы и достоверность её отчётности.

Это учебная модель организации работ: все длительности и ресурсы условные. В ней нет расчёта ядерных процессов, реальных радиационных величин или процедур эксплуатации ядерного оборудования.

Веб-версия: https://spectr-lab-anton-1108.piledcashew1.chatgpt.site — частный сайт с доступом владельца через авторизацию. Репозиторий исходников: https://github.com/ColdmanAnt/spectr-multiagent-lab — частный; для проверки преподавателю потребуется отдельно предоставить доступ или архив проекта.

## Запуск

Нужен Node.js с поддержкой ES-модулей и встроенного `node:test` (Node.js 20 или новее). Зависимостей и установки пакетов нет.

```sh
node server.mjs
```

Откройте `http://127.0.0.1:4173`. Другой порт:

```sh
node server.mjs --port 8080
```

Если Node.js не установлен, веб-интерфейс можно запустить средствами Python 3:

```sh
python3 -m http.server 4173 --bind 127.0.0.1 --directory dist
```

Не открывайте `index.html` двойным щелчком: браузер должен загружать ES-модули через HTTP. Сервер нужен для выдачи файлов; сама симуляция выполняется в браузере. Пакетные эксперименты и тесты требуют Node.js.

## Нужен ли AI API?

Нет. Агент здесь — программный участник со своим состоянием, локальной информацией, целью и правилами выбора. Он отправляет типизированные сообщения другим участникам, оценивает предложения и принимает решения по явному алгоритму.

Ни OpenAI API, ни токен другой модели, ни платные сервисы не используются. После загрузки файлов симуляция работает локально. Случайная нагрузка определяется `seed`, поэтому одинаковые настройки воспроизводят один и тот же эксперимент. Логика находится в `dist/engine.js`, а не в скрытых запросах к модели.

## Что попробовать

1. Выберите распределение задач, сценарий, переговоры и защиту. Задайте `seed`.
2. Запустите смену или выполняйте её по одному такту. Следите за роботами, очередями установок и сообщениями.
3. Повторите тот же сценарий с другим механизмом распределения, сохранив seed и остальные настройки.
4. Внесите сбой кнопкой во время работы. Для сравнения с защитой и без неё внесите один и тот же сбой на одном и том же такте.
5. Откройте «Агенты», чтобы изучить роли и цели; «Эксперименты» — чтобы сравнить несколько прогонов; «Как устроено» — для объяснения модели.
6. Экспортируйте трассу JSON и результаты CSV. Это приложения к отчёту, а не готовые выводы исследования.

Перезапуск смены создаёт новое начальное состояние с выбранными настройками. Скорость воспроизведения влияет на просмотр, а не на число условных тактов работы оборудования.

## Проверки и пакетные эксперименты

```sh
node --test tests/*.test.mjs
node experiments.mjs --seeds 20 --scenario normal --out results/normal
node experiments.mjs --seeds 20 --scenario all --compare-protection --out results/reliability
```

Эксперимент сравнивает четыре сочетания: центральное распределение / контрактная сеть × переговоры выключены / включены. `--compare-protection` добавляет те же прогоны без защитных проверок. Каждый вариант получает тот же seed. По умолчанию один прогон длится 180 тактов. Полная справка: `node experiments.mjs --help`.

Файлы `runs.csv` содержат отдельные прогоны, `summary.csv` — средние и выборочные стандартные отклонения, `experiment.json` — настройки и все строки. Полученные числа описывают именно эту модель и выбранную нагрузку.

## Отчёты и данные исследования

В `reports/` находятся четыре отдельных законченных отчёта по лабораторным работам 1–4: каждый в DOCX и PDF, по пять страниц. Титулы оформлены на имя Холодкова Антона Евгеньевича, НИЯУ МИФИ, группа Б24-517, преподаватель Евгений Николаевич Лагунцев. Отчёты содержат фактические результаты, ограничения модели, таблицы, графики и диаграммы архитектуры.

В `results/reliability/` сохранена серия из 800 прогонов: seed 1–20, 180 тактов, пять сценариев, два механизма распределения, переговоры выключены/включены и защита выключена/включена. `results/traces/` содержит 12 подробных трасс. В `results/manifest.json` записаны SHA256 движка, скриптов эксперимента и проверки, а также трёх файлов серии; версия Node.js, настройки и результат проверки серии текущим движком. `results/test-output.txt` — результат 18 тестов. Обнаруженные исправления и фактический охват повторной проверки описаны в [журнале аудита](docs/audit.md).

Для обновления результатов после изменения модели сначала повторите серию, затем соберите доказательные материалы и пересоздайте DOCX:

```sh
node experiments.mjs --seeds 20 --scenario all --compare-protection --out results/reliability
node tools/capture_evidence.mjs
python3 tools/build_reports.py
```

Перед заменой трасс и manifest скрипт `capture_evidence.mjs` заново выполняет все 800 конфигураций и сверяет каждую сохранённую строку с текущим движком. Он также проверяет полный план без пропусков и повторов, настройки, средние и выборочные стандартные отклонения, соответствие обоих CSV файлу `experiment.json`. При отсутствии или несогласованности данных скрипт завершается с ошибкой; успешный manifest содержит `verifiedAgainstEngine: true`. Затем сохраняются 12 трасс, контрольные суммы и фактический вывод тестов. Этот шаг подтверждает согласованность данных и исходников; оформление DOCX/PDF проверяется отдельно.

Для генератора отчётов отдельно нужны Python 3, `python-docx` и Pillow; само приложение их не использует. Данные титулов задаются в `report-metadata.json`. Генератор проверяет соответствие SHA256 движка сохранённому manifest. После изменения DOCX нужно заново экспортировать PDF и проверить все страницы. PDF в поставке получены из тех же DOCX через изолированный headless renderer.

## Исходники

| Файл | Назначение |
| --- | --- |
| `dist/engine.js` | Состояния агентов, сообщения, распределение, переговоры, сбои и метрики |
| `dist/app.js` | Визуализация, управление сменой и экспорт |
| `dist/index.html`, `dist/style.css` | Интерфейс без сторонних библиотек |
| `tests/engine.test.mjs` | Проверки воспроизводимости и инвариантов модели |
| `experiments.mjs` | Пакетные парные эксперименты и выгрузка данных |
| `server.mjs` | Локальная выдача статических файлов |
| `docs/architecture.md` | Архитектура и протоколы взаимодействия |
| `docs/experiments.md` | План исследования и трактовка метрик |
| `docs/lab-report-guide.md` | Четыре отдельных шаблона отчётов |
| `docs/audit.md` | Исправления, результаты и границы повторной проверки |
| `reports/` | Четыре готовых отчёта в DOCX и PDF с фактическими данными |
| `results/` | 800 прогонов, 12 трасс, вывод тестов и контрольные суммы |
| `tools/build_reports.py` | Генератор отчётов из сохранённой серии |
| `tools/capture_evidence.mjs` | Проверка серии текущим движком и сохранение трасс, контрольных сумм и вывода тестов |

Исходники открыты для чтения и изменения в этом каталоге. Автоматическая регистрация, авторизация, облачная база данных и передача содержимого лаборатории внешнему AI отсутствуют. Состояние смены хранится в памяти вкладки; для сохранения используйте экспорт.
